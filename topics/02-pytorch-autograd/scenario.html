项目场景：预测订单打包耗时

预设需求：仓库想根据订单商品件数，预测一个订单大概要打包几分钟，用来安排拣货和发货节奏。

需求先翻成模型语言

业务输入

订单商品件数，记作 x。比如一单有 2 件商品，x 就是 2。

参考答案

历史订单真实打包耗时，记作 target。比如这单实际用了 5 分钟。

模型假设

先用最简单的线性模型：prediction = w*x+b。w 表示每多一件商品增加多少分钟，b 表示基础打包耗时。

训练目标

让 prediction 尽量接近 target。差得越多，loss 越大，参数就越需要调整。

一次训练到底发生了什么

输入样本

x 是订单商品件数，target 是真实耗时。

forward

用当前参数算 prediction。

loss

比较 prediction 和 target，得到这次错得多严重。

backward

算 w.grad 和 b.grad，判断谁该承担多少责任。

optimizer.step

按学习率更新 w 和 b。

名词和项目需求怎么对应

名词 在这个项目里是什么 人话理解
特征 feature 订单商品件数 x。 模型能看到的输入信息。
target 历史订单真实打包耗时。 参考答案，不是模型猜的，是数据里给的。
参数 parameter w 和 b。 模型通过训练学出来的经验值。
loss 预测耗时和真实耗时的差距平方。 错得越离谱，这个数字越大。
grad w.grad 和 b.grad。 告诉我们 w、b 分别该往哪个方向改。
backward 从 loss 倒着算出 w.grad、b.grad。 追责：这次预测错了，哪些参数负责。
optimizer.step 根据 grad 改 w 和 b。 真的动手修正模型经验。
zero_grad 下一单训练前清空旧 grad。 上一单的责任不要混到这一单里。
