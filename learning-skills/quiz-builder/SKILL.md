# Quiz Builder

用于给某个知识点制作学习型练习题和互动答题页面。

## 触发场景

当用户说“出题”“做练习题”“做测验”“把这个知识点考一考”“做前端交互题库”时使用。

## 核心目标

练习题不是为了难倒用户，而是为了帮用户检查：

- 是否理解整体流程。
- 是否能区分容易混的概念。
- 是否能把公式对应到变量。
- 是否能从代码里找到对应位置。
- 是否能解释训练现象，比如 loss 下降、过拟合、学习率过大。

## 出题顺序

题库必须按这个顺序组织：

1. **流程题**：先问这个知识点整体在干什么。
2. **分工题**：区分概念职责，比如前向传播、反向传播、梯度下降。
3. **结构题**：问变量、参数、层、输入输出维度。
4. **小计算题**：只用低维数字，服务直觉，不做繁琐计算。
5. **现象判断题**：根据训练/验证表现、loss 曲线、输出分数判断问题。
6. **复盘题**：让用户用人话解释。

## 题型组合

每套题至少包含：

- 选择题：快速辨析概念。
- 填空题：主动回忆公式或结果。
- 小计算题：计算 loss、参数更新、参数量等。
- 代码对应题：问某个流程对应到哪段代码或哪个函数。
- 现象判断题：判断欠拟合、过拟合、学习率问题、训练/预测阶段差异。

## 来源参考规则

- 可以参考公开课程、教材、官方文档或学习科学资料。
- 必须改写成当前 demo 的语境，不能照搬题干。
- 每题要标注来源参考，如 `CS231n`、`MIT 6.390`、`本项目 demo`。
- 如果用户要求联网找题，先查可靠来源，再总结这些来源的出题原则。
- 来源主要服务题目设计，不要把外部题目原文大段复制进项目。

## 前端交互要求

练习页必须是静态可打开页面，优先用 HTML + CSS + JavaScript。

必须包含：

- 分类筛选。
- 即时反馈。
- 提示按钮。
- 错题复盘。
- 正确率或进度显示。
- 可选的辅助小工具，比如参数量小算盘、loss 计算器、梯度方向演示。

## 防泄题规则

这些是硬性验收项：

- 选择题正确答案不能全部显示为 A。
- 如果题目数据内部把正确答案写在第一个选项，页面显示时必须打散选项顺序。
- 打散后，提交判断必须仍然按原始正确答案索引判断。
- placeholder、标题、按钮文字、提示文本不能直接泄露答案。
- 小计算题的输入框不能写 `例如 正确答案`。
- 提示只能给解题路线，不能直接给最后答案。
- 提交后才能展示完整解析。

## 反馈文案规则

反馈要回答：

```text
为什么这个答案对？
错误选项容易混在哪里？
它和代码或流程的哪一步对应？
```

不要只写“正确”或“错误”。

## 自检清单

完成题库后必须检查：

- [ ] 正确答案在 A/B/C/D 上有分布，不全是 A。
- [ ] 填空题 placeholder 不泄露答案。
- [ ] 提示不直接给最终答案。
- [ ] 每题有解释。
- [ ] 每题有分类和难度。
- [ ] 每题有来源参考。
- [ ] JS 语法检查通过。
- [ ] 页面入口已加到主题 README、首页或相关导航。
- [ ] 如果仓库已有远程，提交并尝试推送。

## 推荐验证命令

检查 HTML 内联脚本语法：

```powershell
node -e "const fs=require('fs'); const html=fs.readFileSync('topics/主题目录/quiz.html','utf8'); const scripts=[...html.matchAll(/<script>([\s\S]*?)<\/script>/g)].map(m=>m[1]); for (const script of scripts) new Function(script); console.log('script syntax ok:', scripts.length);"
```

检查是否存在泄题 placeholder：

```powershell
rg "例如|placeholder" topics/主题目录/quiz.html
```

检查入口：

```powershell
rg "quiz.html|练习题" .
```
